# Blind WaterMark Studio

> **FFT 频域盲水印工具** —— 网页版 + 安卓 App
> 水印的 **合成 / 分离 / 检测**，兼容 [chishaxie/BlindWaterMark](https://github.com/chishaxie/BlindWaterMark) 的算法实现

把水印图打散成噪声状的图案，直接叠加到位图的**频域**上。画面看不出差别，
但只要有原图，就能用频谱差分把水印精确捞回来。

## 功能

- **合成** —— 载体图 + 水印图 → 带盲水印的图，实时给出 PSNR / 最大像素偏差 / RMS 误差
- **分离** —— 原图 + 含水印图 → 还原出水印，附「增强显示」把压在灰噪声上的轮廓拉出来
- **检测** —— 判定图中是否存在盲水印，可选用候选水印核对（归一化互相关打分）

---

## 算法原理

对每个通道，记原图频谱为 `F1`、水印图案为 `R`：

```
合成:  img_wm = real( ifft2( fft2(img) + alpha × R ) )
分离:  R      = real( ( fft2(img_wm) − fft2(img) ) / alpha )
```

其中 `R` 的构造分三步：

1. 取一块 `(高/2, 宽)` 的空画布，把水印贴到左上角；
2. 用 `seed` 驱动伪随机洗牌生成两个置换 `m`、`n`，令 `hwm[i][j] = hwm2[m[i]][n[j]]`
   —— 水印被彻底打散，看起来像噪声；
3. 把 `hwm` 以 180° 翻转的方式镜像铺满整张画布，得到 `R`。

分离时按 `m`、`n` 把位置还原回去即可。

## 两个必须知道的技术细节

### 1. `np.fft.fft2` 的变换轴陷阱

原作 `bwmforpy3.py` 写的是 `np.fft.fft2(img)`，而 `img` 的形状是 `(H, W, 3)`。
numpy 的 `fft2` 默认 `axes=(-2, -1)`，对三通道数组而言实际变换的是
**宽度轴和通道轴** —— 等价于逐行做 `(W, 3)` 的二维变换，
而**不是**「每个颜色通道各做一次空间二维 FFT」。

验证方法：

```python
f = np.fft.fft2(img)              # img 形状 (H, W, 3)
print(f[0,0,0].real)              # 等于 img[0,:,:].sum()  → 变换轴是 (1,2)
                                  # 而不是 img[:,:,0].sum()
```

**不复刻这一行为，两个实现就互相解不出来。** 本项目的两个版本都忠实复刻了它，
并在界面上提供切换：

| 模式 | 行为 | 画质（512×512，alpha=3） | 与 Python 互通 |
|---|---|---|---|
| **兼容原作**（默认） | 复刻上述变换轴 | PSNR ≈ 40.7 dB，残差为周期性横条纹 | ✅ |
| **高质量** | 每通道独立空间二维 FFT | PSNR ≈ 57.6 dB，残差几乎为零 | ❌ |

### 2. 解码图的对角双影是原作固有缺陷

原作第 3 步用的是 `rwm[H-1-i][W-1-j]`，这是**翻转**对称；
而 DFT 意义上的对称是 `(H-i) mod H`（循环移位），两者**相差 1 个像素**。

后果是 `fft2(real(ifft2(R))) = (R + R_flip) / 2`，约一半能量无法还原，
表现为解码图出现 **1 像素对角双影**、首行首列半亮度。

本项目为保持互通而忠实保留了这一行为，没有"修正"它。

## 检测判据

原作没有检测能力（必须给原图才能分离）。本项目补上了一个：

水印只叠加在频域的**实部**上，所以 `d = fft2(img_wm) − fft2(img)` 在理想情况下是**纯实数**的。
若图中没有水印，`d` 就只剩量化与压缩噪声，实部与虚部能量相当。于是：

```
√( E实部 / E虚部 )    ≈ 1.00   → 无盲水印
                      > 10     → 存在盲水印（无损往返时可达 1e14，虚部被压到数值零）
```

实测：无关图 **1.0004**，含水印图 **12.7**。判据极干净，且与 `alpha` 正相关。

不给原图时会退化为径向功率谱的启发式盲检 —— 那只是参考指标，
会被图像自身的噪声和纹理干扰，**不能作为判定依据**。

## 使用须知

- **必须有原图**。这是加法式频域盲水印的固有限制 —— 分离本质上是频谱差分，
  没有原图就没有基准。而且原图必须是**加水印之前的那一份原始文件**，
  重新保存过（哪怕只是重新编码）都会解不出来。
- **水印尺寸受限**：高度须小于载体图高度的一半，宽度须小于载体图宽度。
- **用 PNG 保存**。JPEG 是有损压缩，会破坏频域里的水印。
- **不能缩放、裁剪、旋转**含水印图，这些操作会直接毁掉水印。

## 验证情况

核心算法经过两层交叉验证，全部通过：

| 层面 | 方式 | 结果 |
|---|---|---|
| JS ↔ Python | 用 `bwmforpy3.py` 导出测试向量，逐层比对（RNG 序列 → 水印图案 → FFT → encode/decode） | 全绿 |
| 浏览器端 | 注入自检脚本走完整流程（上传→合成→分离→检测→边界报错） | 29/29 |

关键交叉验证数据：

- CPython MT19937 完整复刻，`shuffle(1000)` 的加权校验和与 Python **完全一致**
- `encode` 浮点输出最大误差 **5e-8**；FFT 与 numpy 直接对照误差 **5e-7**（受 JSON 的 10 位有效数字限制）
- 解码中间量 `rwm` 最大误差 **1.2e-12**
- 单像素 +1 扰动实验：判据比值 = **1.0000**（理论预期值）

`uint8` 量化环节存在约 7.6% 的元素差 ±1 —— 这是 rwm 值落在整数边界时，
两套实现的浮点舍入方向不同导致的**必然现象**，不是缺陷。
